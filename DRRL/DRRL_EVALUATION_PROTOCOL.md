# 数据集复用就绪等级（DRRL）评价协议

## 0. 文档状态与边界

- 本文档记录当前已经确认的 DRRL 构念、评级结构和验证边界。
- 本协议独立于面向工程域迁移的数据集工程成熟度等级（ERL）协议。
- 本协议不继承旧 ERL/DRRL 实验的评分、权重、切点、等级或数据。
- 当前尚未通过开发集和独立验证集确定人工时间、修复次数等数值切点；相关位置保留为待校准参数。

## 1. 名称与核心构念

DRRL 指 **Dataset Reuse Readiness Level（数据集复用就绪等级）**。

DRRL 评价：

> 对于指定的数据集版本和复用范围，独立第三方能否以较低的可避免摩擦，完成可核验、可重复的数据复用。

形式化评价对象为：

\[
\operatorname{DRRL}(D,v\mid R,E,M,t)
\]

其中：

- \(D\)：数据集；
- \(v\)：冻结且唯一确定的发布版本；
- \(R\)：预先声明的复用范围，例如科研、商业、衍生作品和再分发；
- \(E\)：冻结的中立评价环境；
- \(M\)：适用的模态或 Cluster 条件字典；
- \(t\)：评价时间。

DRRL 不评价：

- 数据集的工程域迁移潜力；
- 模型或算法性能；
- zero-shot 工程表现；
- 数据集的内在质量总分；
- 模型、系统或部署成熟度。

## 2. 评价单元

DRRL 的基本评价单元是：

> 一个具体数据集的一个冻结版本，在一个预先声明的复用范围下形成的发布物。

项目是否持续维护、社区是否活跃、是否频繁更新，作为补充画像报告，不作为冻结版本达到最高等级的必需条件，也不反向改变该版本已经形成的历史评级。

访问入口和外部依赖可能随时间变化，因此每次评级必须记录评价时间。历史评级表示当时证据和实际执行结果，不自动等同于当前状态。

## 3. 复用范围声明

在评级前必须冻结复用范围 \(R\)，至少声明：

- 是否用于非商业科研；
- 是否用于商业训练或商业产品；
- 是否允许生成、保存和发布衍生作品；
- 是否允许再分发原始数据或其子集；
- 是否存在地域、机构、身份或伦理限制；
- 是否需要注册、审批、协议签署或付费。

许可条款清晰但明确禁止目标复用时，不能判为“复用就绪”。DRRL 既评价许可是否可解释，也评价许可是否实际允许声明范围内的复用。

## 4. 等级结构

DRRL 采用四个累积、非补偿等级。

| 等级 | 等级含义 | 核心退出条件 |
|---|---|---|
| DRRL-1 | 可定位、获准、可获取 | 版本身份唯一；许可允许目标复用；获取路径实际有效；所得内容可以核验 |
| DRRL-2 | 可理解、可解析 | 数据、标签和元数据关系明确；结构、语义、单位和编码可解释；代表性样本能够正确解析 |
| DRRL-3 | 可追踪、可核验 | 来源和处理过程可追踪；公开声明与版本、划分和指标对齐；存在基线声明时能够条件性复现 |
| DRRL-4 | 可独立集成 | 能在中立环境中形成标准化数据对象并重复运行；不依赖未公开知识；可避免摩擦处于受控范围 |

等级由适用硬判据的累积通过状态确定：

\[
\operatorname{DRRL}
=
\max\left\{
l:\text{Level 1 至 Level }l\text{ 的适用硬判据全部通过}
\right\}
\]

不采用加权总分，也不允许一个维度的优势补偿许可、获取、完整性或解析等致命短板。

未满足 DRRL-1 时，不强行赋予成熟度等级，应报告为“低于 DRRL-1”，并区分确认失败与证据不足。

## 5. 通用判据

### 5.1 DRRL-1：身份、权限与获取

| 判据 ID | 判据 | 基本证据要求 |
|---|---|---|
| C1.1 | 数据集身份、发布方和版本能够唯一确定 | 官方页面、发布记录、版本号、发布日期或等价证据 |
| C1.2 | 许可条款能够映射到声明的复用范围 | 许可文件、使用条款、数据使用协议或等价证据 |
| C1.3 | 许可实际允许声明范围内的复用 | 逐项核验科研、商业、衍生和再分发权限 |
| C1.4 | 获取入口在评价时实际有效 | 评价者完成下载、申请或受控访问流程 |
| C1.5 | 获得内容与声明的版本、文件清单或完整性信息一致 | 发布清单、校验和、文件规模或等价身份核验 |

### 5.2 DRRL-2：理解与解析

| 判据 ID | 判据 | 基本证据要求 |
|---|---|---|
| C2.1 | 文件组织和数据结构有明确说明 | 目录说明、模式定义、数据字典或等价证据 |
| C2.2 | 样本、标签、元数据和跨模态关系不存在关键歧义 | 标识符、索引、配对规则或关系表 |
| C2.3 | 类别、字段、单位、坐标、空值和异常值约定明确 | 类别表、字段表、单位和异常值说明 |
| C2.4 | 代表性样本能够在中立环境中执行解析 | 直接执行记录和解析结果 |
| C2.5 | 声称存在官方划分时，划分能够唯一重建 | 样本清单、固定索引、随机种子或生成规则 |
| C2.6 | 通过适用 Cluster 的条件解析判据 | Cluster 专用证据包和计算记录 |

### 5.3 DRRL-3：追踪与声明核验

| 判据 ID | 判据 | 基本证据要求 |
|---|---|---|
| C3.1 | 数据来源及关键转换过程能够追踪 | 原始来源、生成或清洗流程、转换记录 |
| C3.2 | 当前发布物能够与其文档、代码和论文对应 | 版本、提交、归档或内容映射证据 |
| C3.3 | 公开性能声明能够对应到确定的版本、划分和指标 | 声明—版本—划分—指标映射 |
| C3.4 | 声称存在基线时，评价方法不存在关键歧义 | 指标定义、评价代码或无关键歧义的实现说明 |
| C3.5 | 存在基线声明时，评价者完成条件性复现 | 冻结环境、命令、日志、输出及容差判断 |
| C3.6 | 已知限制和可能导致错误使用的条件得到说明 | 限制、排除项、已知问题或等价证据 |

C3.3—C3.5 是条件判据。只有发布方提出基线、榜单或性能声明时才适用。没有承担 benchmark 职能的数据集应记为 `N/A`，不因此降级，也不计入适用判据分母。

### 5.4 DRRL-4：独立集成

| 判据 ID | 判据 | 基本证据要求 |
|---|---|---|
| C4.1 | 能够生成标准化清单或等价的中立数据对象 | 生成产物、字段定义和追踪记录 |
| C4.2 | 能够完成适用于该模态的最小读取、索引和数据供给流程 | 可执行适配器、加载记录或等价证据 |
| C4.3 | 相同输入和配置能够重新构建相同的数据对象 | 重复运行记录、散列或结构一致性结果 |
| C4.4 | 不需要未公开知识或无法记录的人工判断 | 完整操作记录及未文档化决策审计 |
| C4.5 | 不存在阻塞性的人工修复 | 修复清单、阻塞记录和裁决结果 |
| C4.6 | 可避免摩擦满足冻结的判定规则 | 人工时间、干预、重试等指标；数值切点待校准 |

## 6. 标准化最小复用事务

DRRL 不是只审查文档的量表。评级者必须实际执行一次标准化最小复用事务：

```text
登记数据集、版本与复用范围
→ 获取发布物
→ 核验身份与完整性
→ 解析代表性样本、标签和元数据
→ 执行 Cluster 条件检查
→ 核验来源与公开声明
→ 条件性复现基线
→ 接入中立数据环境
→ 重复运行
→ 记录全部摩擦与人工干预
```

直接执行结果优先于发布方声明。文档声称可用但实际执行失败时，应依据实际失败结果裁决。

## 7. 中立评价环境

每次评级必须冻结并记录参考环境 \(E\)，至少包括：

- 操作系统和硬件架构；
- 运行时、核心依赖和版本；
- 网络、身份认证和访问条件；
- 文件系统和存储条件；
- 使用的获取、校验、解析和接入工具；
- 允许的人工操作范围；
- 评价命令、配置和日志位置。

中立环境用于确保执行结果可重复，不用于绑定某个特定训练框架或模型。

## 8. 判据状态与证据规则

每项判据采用以下状态：

| 状态 | 含义 |
|---|---|
| `EXECUTED_PASS` | 已通过直接执行验证 |
| `DOCUMENTED_PASS` | 文档证据充分；仅适用于允许文档证据的判据 |
| `FAIL` | 已有证据确认不满足 |
| `UNKNOWN` | 证据不足或无法完成核验 |
| `N/A` | 根据预先冻结的适用性规则不适用 |

证据规则：

1. 每项判据必须预先声明可接受的证据类型。
2. 执行型判据不能仅凭文档声明判为通过。
3. `UNKNOWN` 不等于 `FAIL`，但不能支持等级晋升。
4. `N/A` 必须有适用性依据，并从适用判据分母中排除。
5. 直接执行失败可以推翻与其冲突的书面声明。
6. 所有判据状态必须能够追溯到具体证据、命令、日志或人工裁决记录。

### 8.1 证据质量与字段权威性

DRRL 与独立 ERL 协议采用一致的 Q3—Q0 证据质量语言：

| 级别 | 定义 | DRRL 使用方式 |
|---|---|---|
| Q3 | 对实际发布物、许可流程、文件、标签、元数据或复用事务直接执行、计算或复核 | 执行型判据的主要依据 |
| Q2 | 对应版本的官方许可、数据卡、规范、论文、仓库或发布记录 | 文档型判据可采用；支持执行解释 |
| Q1 | 二手综述、非官方网页或不可复算声明 | 仅作为检索线索 |
| Q0 | 无证据或冲突无法解决 | 记为 `UNKNOWN` |

Q3—Q0 表示证据的直接性和可复核性，不是一套适用于所有字段的单一来源排名。
发生冲突时还必须按字段采用相应权威来源：

- 许可和权利以当前正式许可文本或数据使用协议为准；
- 文件规模、内容和标注以实际发布物、冻结清单和直接执行结果为准；
- 版本和发布身份以官方版本记录、归档或 DOI 为准；
- 任务语义和采集协议以对应版本的官方数据卡、规范或原始论文为准；
- 论文身份以出版方和 DOI 注册记录为准。

同等质量、同等字段权威性的来源仍冲突时，必须保留 `UNKNOWN` 或冲突记录，不得
按来源数量、Agent 数量或模型自报置信度表决。

### 8.2 Agent 证据状态映射

采用多 Agent 证据评价流程时，其 `ACCEPTED`、`REJECTED`、`NOT_EVIDENCED`、
`NOT_APPLICABLE`、`ACCESS_BLOCKED` 和 `UNRESOLVED_AFTER_REVIEW` 是证据处理状态，
不是新增 DRRL 判据状态。确定性判定程序按下列原则映射：

- `ACCEPTED` 证据根据内容支持既有判据通过或失败；
- `REJECTED` 仅淘汰候选证据，不直接等于 `FAIL`；
- `NOT_EVIDENCED` 和未解决冲突映射为 `UNKNOWN`；
- `NOT_APPLICABLE` 映射为 `N/A`；
- 经直接执行归因确认的 `ACCESS_BLOCKED` 按相应访问/获取判据裁决；
- `RUN_INCOMPLETE` 不得进入评级。

Agent 实验的角色、盲核验、重试和完成规则见
[`../AGENT_EVALUATION/AI_AGENT_EVALUATION_PROTOCOL.md`](../AGENT_EVALUATION/AI_AGENT_EVALUATION_PROTOCOL.md)。

## 9. 可避免摩擦与资源负担

### 9.1 复用摩擦

DRRL 记录的可避免复用摩擦至少包括：

- 人工操作时间；
- 阻塞事件数量；
- 手工修复数量；
- 未文档化决策数量；
- 失效依赖和环境冲突；
- 重试次数；
- 需要发布方协助的次数；
- 无法自动化的关键步骤。

### 9.2 资源负担

资源负担单独形成 `resource_burden` 画像，至少包括：

- 数据体量；
- 存储需求；
- 网络传输需求；
- 运行内存；
- 参考计算资源；
- 预期处理时长。

数据规模、下载时长和计算需求本身不直接降低 DRRL。只有当发布物缺少与其规模相适应的获取、校验、分片、恢复或读取机制，或者实际资源需求与发布声明明显不一致时，才影响 DRRL 判据。

## 10. Cluster 条件字典

DRRL 采用“通用核心协议＋条件复用核验字典”：

```text
通用核心协议
├── 身份、版本与复用范围
├── 获取与完整性
├── 语义、结构与解析
├── 来源、转换与声明核验
├── 条件性基线复现
└── 中立环境集成与摩擦记录

条件复用核验字典
├── Cluster A：二维病害影像
├── Cluster B：RGB-T
├── Cluster C：三维点云
└── Cluster D：城市资产
```

当前条件字典：

- [Cluster A：二维基础设施病害影像](reuse_verification_dictionaries/CLUSTER_A_2D_DEFECT_REUSE_VERIFICATION_DICTIONARY.md)
- [Cluster B：RGB–Thermal 配对数据](reuse_verification_dictionaries/CLUSTER_B_RGBT_REUSE_VERIFICATION_DICTIONARY.md)
- [Cluster C：三维城市与基础设施点云](reuse_verification_dictionaries/CLUSTER_C_3D_POINT_CLOUD_REUSE_VERIFICATION_DICTIONARY.md)
- [Cluster D：城市资产与城市场景数据](reuse_verification_dictionaries/CLUSTER_D_URBAN_ASSET_REUSE_VERIFICATION_DICTIONARY.md)

字典核验项是通用核心判据的可执行子检查，不增加新的 DRRL 等级，也不形成额外权重。不同 Cluster 的核验项数量不得直接合并为总分或共同的完备度分母。

对任一核心判据 \(C_j\)，先冻结其适用子检查集合 \(S_j\)，再按非补偿规则汇聚：

1. 任一适用子检查为 `FAIL`，则 \(C_j\) 为 `FAIL`；
2. 无 `FAIL` 但任一适用子检查为 `UNKNOWN`，则 \(C_j\) 为 `UNKNOWN`；
3. 其余适用子检查均以该判据要求的证据类型通过时，\(C_j\) 才能通过；
4. `N/A` 必须有预先冻结的适用性依据，并从 \(S_j\) 中排除；
5. 主证据完备度按通用核心判据计算，字典子检查完备度另行报告。

条件字典只规定复用所需的解析、关系核验和接入检查。例如：

- Cluster A：图像—标签对应、掩膜或检测框编码、图像尺寸与切片关系；
- Cluster B：RGB 与热红外模态身份、配对、同步和缺失模态表示；
- Cluster C：坐标系、单位、类别编码、点属性和分块规则；
- Cluster D：空间参考、资产身份、时间字段、几何—属性关系和多源关联。

条件字典不评价工程覆盖度、标注纯度、捷径风险或域迁移潜力。这些属于独立 ERL 协议。

## 12. DRRL 与 ERL 的关系

DRRL 不完整包含 ERL，ERL 也不参与 DRRL 判级。

| DRRL | ERL | 数据集状态解释 |
|---|---|---|
| 高 | 高 | 易于第三方复用，且对指定工程应用具有较强迁移潜力 |
| 高 | 低 | 易于第三方复用，但对指定工程应用的迁移潜力有限 |
| 低 | 高 | 数据可能具有工程价值，但第三方获取、理解、核验或接入障碍较大 |
| 低 | 低 | 复用条件和工程迁移潜力均不足 |

DRRL 报告只允许通过以下可选字段引用独立 ERL 结果：

```yaml
optional_erl_reference:
  assessment_available:
  protocol_reference:
  application_envelope_id:
  verified_erl:
  evidence_completeness:
```

同一份原始证据可以被两套协议分别引用，但必须依据不同构念独立裁决，不得继承判据状态、换算等级或将 ERL 完整嵌入 DRRL。

## 13. 评级流程

1. 唯一确定数据集和冻结版本。
2. 冻结复用范围、评价时间、参考环境和 Cluster。
3. 冻结条件判据适用性矩阵。
4. 保存许可、发布页、文档、代码和文件清单等证据快照。
5. 执行标准化最小复用事务。
6. 记录命令、日志、耗时、阻塞、修复和未文档化决策。
7. 按证据规则裁决各项判据状态。
8. 依据累积必要条件推导已验证 DRRL。
9. 输出证据完备度、主要阻塞项、摩擦画像和资源负担。
10. 如存在独立 ERL 结果，仅通过可选接口进行引用。

## 14. DRRL 的效度验证

DRRL 评级规则和数值切点冻结后，再由未参与评级规则开发的独立第三方执行复用任务，验证 DRRL 能否预测：

- 获取成功率；
- 首个有效样本时间；
- 首次有效接入时间；
- 阻塞事件和人工修复数量；
- 未文档化决策数量；
- 条件性基线复现成功率；
- 独立重复运行成功率。

主统计单位必须是“数据集发布版本”，不能把单个文件、命令次数、随机种子或操作日志当作相互独立的数据集样本。

效度验证应将规则开发数据集与独立验证数据集分开，避免用同一批复用任务既拟合切点又证明协议有效。

DRRL 的预测假设仅限于：等级越高，独立第三方完成复用事务的成功率越高、可避免摩擦越低。DRRL 不预测 zero-shot 工程表现，也不能替代 ERL 的预测效度验证。

## 15. 当前待校准内容

以下内容不得在缺乏开发集证据时任意设定：

- DRRL-4 可接受的人工操作时间；
- 可接受的修复、重试和发布方协助次数；
- 基线复现容差；
- 证据完备度的报告切点；
- 各 Cluster 条件判据的抽样方法和最低覆盖率；
- 中立环境的具体实现和允许依赖；
- 复用范围模板的标准字段；
- 独立效度验证的样本量与成功判据。

上述参数应通过开发数据集拟合，冻结后在独立数据集上验证；任何后续修订必须保留规则、证据和结果的完整追踪关系。
