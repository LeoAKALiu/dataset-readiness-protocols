## 1. 研究背景与总体目的

城市更新与城市体检涉及基础设施病害识别、多模态巡检、三维场景建模和城市资产
识别。既有公开数据集的任务、模态、标签、采集条件、发布形式和复用条件高度异质，
单纯以样本规模、论文引用量或已发表模型性能，无法同时回答以下两个问题：

1. 独立第三方能否低障碍、可核验地复用指定发布版本；
2. 在目标工程案例出现前，源数据是否具备支持 zero-shot 工程域迁移的必要数据条件。

本研究建立两条相互独立的测量与效度链：

```text
DRRL：发布物与复用证据 → 独立第三方复用结果
ERL：源数据可观察属性 → 未见工程案例 zero-shot 结果
```

本研究的总体目的不是形成统一的“数据集质量总分”，而是：

- 建立城市更新与城市体检数据集的可追溯领域地图；
- 分别测量 DRRL 和 ERL；
- 评价多 Agent 证据流程的准确性、覆盖率和重复性；
- 检验 DRRL 对第三方复用结果的效度；
- 检验 ERL 对未见工程案例迁移表现与失效风险的预测效度。

## 2. 研究问题、假设与结论层级

### 2.1 研究问题

| 编号 | 研究问题 |
|---|---|
| RQ1 | 公开数据集在任务、模态、工程用途和发布形态上形成怎样的领域格局？ |
| RQ2 | 数据集的 DRRL、ERL、证据完备度、Q3 覆盖率和主要瓶颈如何分布？ |
| RQ3 | 双 Agent 证据流程能否准确、稳定、可复核地执行 DRRL/ERL 评价？ |
| RQ4 | DRRL 是否与独立第三方复用成功率和可避免摩擦呈预期关系？ |
| RQ5 | ERL 是否与未见目标工程案例的 zero-shot 表现、稳定性和失效风险呈预期关系？ |

### 2.2 确认性假设

以下方向性假设仅在相应规则、样本拆分和主要终点冻结后进入确认性检验：

- **H-A（Agent 核验增益）**：相对于检索 Agent 的原始确定性结论，经过盲核验后的
  错误确定结论率更低；同时报告覆盖率变化，禁止用大量弃答换取表面准确率。
- **H-D（DRRL 效度）**：DRRL 越高，独立第三方复用成功率越高，完成时间、阻塞、
  人工修复和未文档化决策总体越少。
- **H-E1（ERL 平均效度）**：在相同 Cluster 和冻结任务范围内，ERL 越高，源数据集
  在未见目标案例上的平均 zero-shot 表现总体呈预期方向。
- **H-E2（ERL 风险效度）**：在相同 Cluster 和冻结任务范围内，较高 ERL 数据集的
  跨案例波动、最差案例风险和灾难性失败率总体更低。

### 2.3 探索性问题

以下内容不作为确认性成功条件：

- DRRL 与 ERL 的相关性和四象限分布；
- 模型、角色、来源类型或 Cluster 对 Agent 误差的调节作用；
- 单个 ERL 原始指标与迁移表现的剂量—反应关系；
- 不同非补偿聚合结构的比较；
- 受控数据损伤实验所揭示的机制差异。

DRRL 与 ERL 不得合成为总分。二者不相关、弱相关或相关均不能单独证明构念区分；
区分效度主要依据定义边界、判据内容和各自外部效标。

## 3. 研究总体设计

本研究采用多阶段、前瞻性、开发—验证分离的混合设计，包括：

1. 系统性数据集发现、身份归一和领域地图；
2. 基于公开证据与直接执行证据的 DRRL/ERL 观察性评价；
3. 多模型双 Agent 证据流程的方法学审计；
4. 独立第三方复用研究，用于 DRRL 效度验证；
5. 多源数据集、多模型、多随机种子和多独立目标案例的 zero-shot 实验，用于 ERL
   阈值开发和独立预测效度验证。

各实验模块共享数据集身份和证据图，但不得共享不应暴露的结果。尤其是 ERL 评价
人员、Agent 和阈值开发程序在协议规定的解盲时点前不得接触独立目标案例表现。

## 4. 研究对象、Cluster 与统计单位

### 4.1 数据集领域总体

当前证据地图包含 115 个候选数据集家族，其中 54 个 `include`、44 个
`provisional`，共 98 个家族进入当前主评价候选池。正式数量以 `registry_lock` 为准。

数据集身份采用三层证据图：

```text
数据集家族 → 明确发布版本 → 发布—任务评价单元
```

- DRRL 单元：`family + explicit release + reuse scope + assessment time`；
- ERL 单元：`family + explicit release + Cluster + application envelope`；
- 领域地图和总体不确定性：以数据集家族为聚类单位，家族等权；
- 复合数据集不作为新增独立采集家族增加统计权重。

### 4.2 Cluster 定义

| Cluster | 固定范围 |
|---|---|
| A | 二维基础设施表面或结构病害影像 |
| B | RGB–Thermal 配对多模态巡检数据 |
| C | 三维城市或基础设施点云 |
| D | 城市场景与城市资产识别数据 |

不同 Cluster 的 ERL 不作数值等值比较。同一 Cluster 内不同任务也必须分别定义
应用范围、标签映射、性能终点和效度结论。

### 4.3 不可替代的统计单位

| 模块 | 主要统计单位 | 重复测量或嵌套单位 |
|---|---|---|
| Agent 方法审计 | 数据集家族的代表性评价单元 | 字段、模型、角色、重复运行 |
| DRRL 效度 | 明确的数据集发布版本 | 独立操作者、命令、重复执行 |
| ERL 效度 | 独立源数据集家族 | 目标案例、模型、随机种子、图像/点/像素 |
| 目标案例质量 | 独立工程案例 | 资产、序列、扫描、帧、目标、像素或点 |

模型、随机种子、文件、字段、图像、点和像素不得作为独立数据集扩大样本量。

## 5. 阶段与实验模块

### 5.1 阶段 0：技术可行性与协议锁定

阶段 0 使用每个 Cluster 2 个家族，共 8 个家族，验证：

- 发布和任务单元登记；
- 检索、盲核验、第三复核和确定性程序的角色隔离；
- 提示词、schema、证据包和完成清单；
- 网络波动、限流、OAuth 和服务端异常的重试与断点续跑；
- 原始证据、正式评分文件与调试日志的隔离；
- DRRL 与 ERL 两条流水线的命名空间和盲化；
- 资产不可访问、证据冲突和运行未完成时的状态映射。

阶段 0 只用于发现技术缺陷和冻结正式协议，不进入主要科学结果，也不得用于
选择有利模型、数据集或结论。

阶段 0 后至少冻结：

- `registry_lock`；
- `protocol_lock`；
- 模型 `panel_manifest`；
- 提示词、schema、程序和字典哈希；
- 主评价流程与审计抽样；
- 网络缓存、重试和完成规则；
- 预注册分析计划。

### 5.2 实验 1：领域地图与双就绪度画像

对冻结主评价池执行：

1. 建立家族、发布和任务节点；
2. 对主发布版本执行 DRRL 评价；
3. 对全部家族报告 ERL 资产可评状态；
4. 对可评发布—任务单元计算 ERL 原始指标和证据状态；
5. 在阈值冻结前只报告原始画像，不提前生成正式 ERL 等级；
6. 阈值冻结后，对符合盲化条件的单元按固定规则推导等级；
7. 分别报告等级、证据完备度、Q3 覆盖率、关键短板、未知项和冲突项；
8. A/B/C/D 分层报告，保留家族数和评价单元数。

领域地图分析以描述性统计和区间估计为主，不用数据集数量、样本量或引用量推导
准备度。

### 5.3 实验 2：多 Agent 证据评价方法审计

#### 样本与运行

- 32 个家族接受五模型审计：每 Cluster 8 个；
- 16 个家族接受独立测试—重测：每 Cluster 4 个；
- 审计抽样排除阶段 0 家族，并在正式评价前按固定哈希确定；
- DRRL 按现行协议完整执行；
- ERL 仅对满足资产可评条件的单元执行，运行量以
  (N_E)、(N_{EA})、(N_{ER}) 参数化报告；
- DRRL 与 ERL 使用不同提示词、输出命名空间和角色调用，不在同一 Agent 输出中
  合并评价。

#### 人工参考

- Cluster 学生进行主核验；
- 第二名学生轮换复核全部等级相关字段；
- 两名核验者对模型身份、Agent 输出和 Agent 等级保持盲化；
- 分歧由项目负责人统一裁决；
- 人工参考在与 Agent 输出匹配前冻结。

#### 主要终点

- 来源发现率；
- 标准化字段精确或容差一致率；
- 证据终态一致率；
- 错误引用率；
- 必填证据遗漏率；
- 来源—声明不匹配率；
- 错误确定结论率；
- Coverage、Conditional Accuracy 和 Overall Correct Resolution；
- 最终等级一致性和测试—重测一致性；
- `RUN_INCOMPLETE`、恢复率和失败类型。

检索者原始输出与盲核验后输出的比较采用同字段配对分析。第三复核仅由冲突或
新增证据触发，因此其结果属于条件性过程分析，不能未经随机分配解释为严格的
因果消融实验。

若 ERL 的人工参考覆盖不足，Agent 方法贡献必须限定为 DRRL 或已审计的 ERL
字段，不得笼统表述为已经验证全部 ERL 评价流程。

### 5.4 实验 3：DRRL 阈值开发与独立效度验证

#### 开发阶段

在开发发布版本上估计并形成以下待校准规则：

- DRRL-4 可接受的人工操作时间；
- 修复、重试和发布方协助次数；
- 条件性基线复现容差；
- Cluster 条件检查的抽样与覆盖规则；
- 中立环境及允许依赖；
- 独立复用事务的主要和次要终点。

开发结果冻结后，不得使用独立验证发布版本修改上述规则。

#### 独立验证阶段

由未参与规则开发和原评级的第三方操作者，在清洁、中立环境中执行标准化最小
复用事务。操作者在执行前不得看到数据集的 DRRL 等级或其他操作者结果。

主要候选终点：

1. 获取成功率；
2. 首个有效样本时间；
3. 首次有效接入时间；
4. 阻塞事件和人工修复数量；
5. 未文档化决策数量；
6. 条件性基线复现成功率；
7. 独立重复运行成功率。

验证样本可按冻结 DRRL 层级和 Cluster 分层抽取，以保证层级覆盖；抽样方法必须
预先登记。若用于估计总体分布，应保留抽样概率并采用相应权重。评级阶段执行的
复用事务不得作为独立验证结果重复使用。

### 5.5 实验 4：ERL 效度可行性门与阈值开发

ERL 预测效度按“一个 Cluster 内的一个冻结任务”逐项开展。购买、采集或标注正式
目标案例前，必须通过以下可行性门：

1. 存在足够数量的独立源数据集家族；
2. 数据集支持相同任务，或能够通过预先冻结且工程语义损失可接受的本体映射对齐；
3. ERL 原始指标和关键短板具有可分析的实际变异；
4. 目标案例能覆盖应用范围，且选择过程不依赖某源数据集的预期表现；
5. 源数据与目标案例之间不存在对象、地点、序列、扫描或近重复泄漏；
6. 能够冻结模型集合、训练预算、预处理、checkpoint 规则和主要终点。

若候选源数据只有一个可确认等级，不进行等级趋势分析；若只有两个等级，只允许
报告两级对比；只有覆盖三个或以上等级时，才分析有序梯度。上述规则是分析边界，
不是预设的效度成功阈值。

开发阶段采用开发源数据集和开发目标案例：

- 检验候选 `V` 判据的必要性角色；
- 形成并冻结候选切点；
- 比较关键门槛、等价证据包和诊断指标的角色；
- 检查非补偿聚合是否存在不可接受的退化或等级坍缩；
- 估计正式验证所需的源数据集数、目标案例数和案例内有效样本量。

受控数据变体可用于机制验证，但不得作为新的独立源数据集增加统计样本量。

### 5.6 实验 5：ERL 独立预测效度验证

#### 双重独立验证

ERL 规则冻结后，使用同时满足以下条件的验证材料：

- 未参与阈值开发的独立源数据集；
- 未参与阈值开发的独立目标工程案例。

开发源数据集、开发目标案例、验证源数据集和验证目标案例的身份及哈希必须在
解盲前登记。若开发后修改任何实质性指标、切点、聚合结构、标签映射、模型流程
或主要终点，原验证材料不再构成当前规则的独立验证集。

#### Zero-shot 实验约束

对每个源数据集：

1. 仅使用该源数据集训练；
2. 使用预先冻结的代表性模型集合；
3. 固定初始化来源、训练预算、损失函数、增强和预处理；
4. 仅允许源内验证集进行 checkpoint 选择；
5. 不使用目标数据调参、早停、选择模型、修改标签映射或调整阈值；
6. 不实施目标域微调、域适配或测试时训练；
7. 在多个未见目标案例上直接推理；
8. 保留全部模型与随机种子结果，不按目标表现选择性报告。

#### 主要终点

每个 Cluster—任务使用其原生工程性能指标，不跨任务合并 mIoU、mAP 等异质终点。
主要候选终点为：

- 跨案例宏平均表现；
- 跨案例标准差、IQR 或预注册的稳定性指标；
- 最差案例表现；
- 灾难性失败率；
- 冻结模型集合中的方向一致性。

案例数不足时，不报告不稳定的 CVaR 或最差分位推断。零次灾难性失败不等于风险
为零，必须报告相应区间上界。

### 5.7 实验 6：双轴联合画像与敏感性分析

在 DRRL 与 ERL 的独立主要分析完成后，可以探索：

- 高 DRRL—高 ERL；
- 高 DRRL—低 ERL；
- 低 DRRL—高 ERL；
- 低 DRRL—低 ERL。

该分析用于识别不同治理与工程失效模式，不形成联合等级、总分或部署建议。联合
分析方案应在观察正式结果支持度后另行登记，并明确标为探索性。

## 6. Cluster 特定实施边界

| Cluster | 主要风险 | 效度实验必须冻结的要点 |
|---|---|---|
| A | 病害本体差异、连拍近重复、尺度与背景捷径 | 分类、检测、语义分割或实例分割中选择一个主任务；冻结最小病害尺度和标签映射 |
| B | RGB/T 身份错误、配对与同步误差、单模态捷径 | 使用真正配对的工程巡检任务；冻结配准、缺失模态和辐射/温度语义规则 |
| C | 点密度、坐标单位、传感器差异和切块伪重复 | 冻结点云任务、坐标和空间独立单元；同一扫描切块不得增加独立样本量 |
| D | 城市、路线与连续帧泄漏，资产本体差异 | 检测与分割分别验证；冻结路线/城市/资产独立性和空间—时间身份规则 |

任何 Cluster 未通过效度可行性门时，仍可进入领域地图、DRRL 和 ERL 原始画像，
但不得承担该 Cluster 的 ERL 预测效度结论。

## 7. 目标工程案例与标注设计

### 7.1 三类样本量

目标案例计划必须分别确定：

- 独立目标工程案例数 (J)；
- 案例内有效独立评价单元数 (n_j)；
- 独立重复标注审核单元数 (n_{a,j})。

增加同一案例中的帧、切块、目标、像素或点不能替代增加独立工程案例。

### 7.2 先导标注

每次只针对一个 Cluster 中的一个冻结任务开展先导标注。当前可执行起点为：

- 3 个独立目标工程案例；
- 每案例约 400 个有效独立评价单元；
- 每案例约 140 个有效独立单元接受两名标注者相互盲态下的独立标注；
- 全部分歧进入专家或第三标注者裁决。

上述数量只用于估计类别发生率、标注误差、案例间方差和簇内相关，不构成正式
充分样本量，也不能支持独立预测效度声明。

### 7.3 正式样本量

正式样本量基于先导数据的层级模拟或簇级 bootstrap 确定，至少考虑：

- 案例间与案例内方差；
- 资产、序列、路线、扫描或场景的簇内相关；
- 关键类别发生率和独立阳性对象数；
- 数据集、模型和案例的交互；
- 计划估计的平均效应、尾部风险和灾难性失败率精度。

不得仅依赖传统以图像、像素或点为 (N) 的功效计算。

### 7.4 标注质量

- 冻结类别本体、标注边界、忽略/不确定规则和输出格式；
- 保留两份原始标注、分歧、裁决和时间戳；
- 主分析使用裁决后的冻结共识标注；
- 分别以两名原始标注者为效标进行敏感性分析；
- 报告漏标、虚假对象、类别错误、边界差异、裁决率和置信区间；
- 按案例、类别和主要环境子组报告质量。

### 7.5 目标案例来源与独立验收

目标工程案例可以由研究团队自行采集标注，也可以采购具有适当研究与发表授权的
成熟私有数据集。采购不替代质量控制。无论来源如何，均须：

- 核验许可、研究使用、模型训练、结果发表和必要衍生物保存权限；
- 在查看源数据集 ERL 和模型结果前冻结采购或纳入标准；
- 由未参与供应方生产流程的人员执行独立验收；
- 按案例、类别和环境条件抽样复标，并对分歧进行裁决；
- 核验案例、地点、资产、序列和采集来源的独立性；
- 保存供应方版本、交付清单、校验和、标注规范、验收结果和复标记录。

供应方声称“成熟”“商用”或“已质检”不构成研究中的标注真值证据。无法取得
足够审计权、使用权或来源信息时，该数据不得进入确认性效度验证。

## 8. 数据拆分、盲化与泄漏控制

### 8.1 拆分层级

- 数据集发现阶段的家族身份不得以预期等级筛选；
- 阶段 0 家族不进入正式 Agent 审计抽样；
- Agent 人工参考在查看 Agent 输出前冻结；
- DRRL 开发发布版本与独立验证发布版本分开；
- ERL 开发源数据集与验证源数据集分开；
- ERL 开发目标案例与验证目标案例分开；
- 分池以家族、项目、地点、资产、序列或扫描等最高独立单元执行。

### 8.2 ERL 盲化

ERL 评价和阈值冻结前：

- 不得查看候选源数据集在目标案例上的表现；
- 不得按目标表现选择模型、种子、数据预处理或标签映射；
- 不得用目标结果修改源数据证据状态；
- 高 ERL 数据集在验证中失败时，应检验规则效度，而不是事后降低该数据集等级。

### 8.3 数据泄漏检查

至少检查：

- 来源家族、派生和复合关系；
- 精确文件哈希；
- 感知或特征近重复；
- 同一视频、路线、扫描、地点、资产或工程项目交叉；
- 训练、验证和目标案例间的标签或元数据泄漏；
- 预训练模型是否已知接触目标案例或同源公开数据。

无法排除基础模型预训练污染时，应记录风险，并通过从头训练或可追溯初始化模型
形成敏感性分析，不得将“未知”表述为“无污染”。

## 9. 统计分析计划

### 9.1 通用原则

- 以估计量、效应量和区间估计为主，不以 `p < 0.05` 组织主要叙事；
- 所有重采样以家族、发布版本、独立案例或其他最高独立单元为单位；
- 多模型、多字段、多种子结果不得产生伪重复；
- A/B/C/D 和不同任务分别分析；
- 主要、次要和探索性终点在解盲前冻结；
- 缺失、不可评、未知和冲突不得自动赋零或最低等级。

### 9.2 Agent 方法分析

- 以家族为单位 bootstrap 置信区间；
- 对检索者原始结果与盲核验后结果计算配对差异；
- 名义状态报告 Gwet's AC1 或 Krippendorff's alpha；
- 有序状态和等级报告 Gwet's AC2 或有序 alpha；
- 同时报告 Coverage、Conditional Accuracy 和 Overall Correct Resolution；
- 将模型、角色和 Cluster 差异标为探索性，避免多模型排名叙事。

### 9.3 DRRL 效度分析

- 二元结果：分层二项模型或等价的聚类稳健分析；
- 完成时间：预注册的生存/删失时间模型或稳健时间比较；
- 阻塞、修复和未文档化决策：适合过度离散的计数模型；
- DRRL 先作为有序分类变量分析，再进行预注册的单调趋势分析；
- 发布版本为主要统计单位，操作者为版本内重复；
- 报告 Cluster、复用范围和资源负担的敏感性分析。

### 9.4 ERL 效度分析

主要分析先将固定模型、随机种子和目标案例的结果按预注册规则汇总到独立源数据集，
再估计 ERL 等级之间的有序差异。补充分析可采用交叉层级模型描述目标案例、模型
和数据集之间的交互。

- 原生性能指标分别建模，不跨任务合并；
- ERL 作为有序分类变量，不默认相邻等级等距；
- Spearman 相关仅作为辅助描述，不设置任意固定相关阈值；
- 稳定性和最差表现按案例层级计算；
- 灾难性失败阈值由工程任务预先规定；
- 检查结论是否由单一数据集、模型或案例驱动；
- 以家族和案例为层级进行 bootstrap 或等价的层级区间估计。

### 9.5 多重性

每个 Cluster—任务预先指定一个主要性能终点和一个主要风险终点。其他类别级、
模型级、指标级和子组分析均为次要或探索性。若进行多项确认性比较，应冻结检验
族并采用适当的错误率控制；不得在观察结果后重新命名主要终点。

## 10. 敏感性与稳健性分析

至少包括：

1. `UNKNOWN` 与 `CONFLICT` 的不同保守处理方式；
2. 已验证等级、证据完备度和 Q3 覆盖率分别建模；
3. 候选阈值在开发不确定区间内扰动；
4. 去除单一数据集、案例、模型或来源后的影响；
5. 家族等权与发布单元等权的差异；
6. 有序等级与原始形成性指标画像的比较；
7. 目标标注者、裁决共识和误差扰动效标之间的比较；
8. 可追溯初始化模型与存在预训练污染风险模型的比较；
9. DRRL/ERL 非补偿结构与补偿性加权结构的探索性比较；
10. 受控重复、噪声、类别删减、元数据破坏和捷径增强实验。

补偿性模型只作为敏感性对照，不取代规范性非补偿等级。

## 11. 停止、降级与失败规则

### 11.1 技术停止

- 运行未完成、证据包不完整或 schema 未通过时，不得评级；
- 网络、限流、OAuth 或服务端错误按预注册策略重试和断点续跑；
- 超出重试上限后标记运行不完整，不归因于数据集；
- 调试日志不得写入正式评分文件。

### 11.2 Cluster 效度降级

出现以下任一情况时，该 Cluster 不进入确认性 ERL 预测效度分析：

- 无法形成共同任务和可接受的标签映射；
- 独立源数据集不足以估计计划效应；
- 原始指标或等级发生不可分析的范围限制；
- 目标案例与源数据无法排除泄漏；
- 目标案例数或标注质量不足以支持计划终点；
- 模型和训练协议无法在源数据集间公平执行。

降级后的 Cluster 仍可报告领域地图、DRRL、ERL 资产可评性和原始画像，但必须
明确“不支持预测效度结论”。

### 11.3 规则失败

- ERL 高等级在独立验证中无预期方向或存在不可接受的尾部失效时，应报告当前
  规则未获得支持；不得事后修改验证数据集等级；
- DRRL 与独立复用结果无预期关系时，应报告相应等级或摩擦切点效度不足；
- Agent 覆盖率或准确性不足时，应将其定位为透明执行工具或半自动框架，不得宣称
  已验证的自动评价方法。

## 12. 伦理、人员与数据治理

本研究不预设一定构成人体研究。正式实验前，应由所属机构依据当地规则判断以下
活动是否需要伦理审查、豁免认定或知情同意：

- 记录独立第三方操作者的完成时间、错误、干预和决策；
- 记录学生核验者或标注者的一致性、工作过程和重复表现；
- 目标案例中可能包含可识别人员、车牌、住址、精确位置或敏感基础设施信息。

无论伦理类别如何，均应：

- 向参与操作者、核验者和标注者说明研究任务、记录字段和退出方式；
- 不把个人表现用于课程成绩、雇佣评价或模型能力排名；
- 论文主要报告汇总结果，不公开可识别的个人错误轨迹；
- 将身份映射与研究结果分离保存，并限制访问；
- 对影像、地理坐标和基础设施敏感信息执行最小化、脱敏和许可约束；
- 在预注册和论文中报告伦理审查或豁免状态。

## 13. 输出、追溯与公开材料

正式研究至少保存：

- 数据集家族、别名、版本和任务注册表；
- `registry_lock`、`protocol_lock` 和 `panel_manifest`；
- Cluster 应用范围、源数据集拆分和目标案例拆分清单；
- DRRL/ERL 单字段证据包和证据状态；
- 直接计算指标、输入清单、参数和程序哈希；
- Agent 原始输出、盲核验结果、第三复核和完成清单；
- 与正式结果隔离的运行诊断日志；
- DRRL 独立复用事务记录；
- ERL 模型训练配置、checkpoint 选择规则和逐案例预测结果；
- 原始标注、复核标注、分歧、裁决和质量报告；
- 统计分析代码、主要结果表和敏感性分析；
- 所有协议偏离、修订和解盲时间记录。

公开材料应删除凭据、私有身份信息和受许可限制的数据内容，同时保留足以复核
来源、程序、参数和结论的结构化证据。

## 14. 主要论文结果模块

建议按以下模块组织结果，但不得为叙事完整性牺牲构念边界：

1. 数据集发现、别名归一和 A/B/C/D 领域地图；
2. DRRL 与 ERL 的独立分布、证据缺口和典型失效模式；
3. 双 Agent 证据流程的准确性、覆盖率、重复性和人工负担；
4. DRRL 对独立第三方复用结果的效度；
5. 按 Cluster—任务报告的 ERL 独立预测效度；
6. DRRL–ERL 四象限的探索性解释。

若只有单一 Cluster 完成严格的 ERL 独立验证，论文必须将结论限定于该
Cluster—任务，或将框架/领域地图与单 Cluster 效度研究拆分发表。不得从单一案例、
单一模型或单一 Cluster 外推到全部城市更新数据集。

## 15. 允许与禁止的结论

### 15.1 阶段 0 后但效度验证前

允许：

> 本研究建立了相互独立的 DRRL 与 ERL 候选协议、Cluster 条件字典和可追溯的
> 多 Agent 证据评价流程，并形成了预注册的外部效度验证设计。

禁止声称协议已经具有预测效度或数据集已获得经过验证的绝对等级。

### 15.2 Agent 审计后

Agent 方法的表述必须依据准确性、覆盖率、一致性和重复性结果分级：

- 证据充分：经经验验证、可复用的双 Agent 评价方法；
- 局部不稳：具有可行性证据的半自动评价框架；
- 准确或覆盖不足：透明的实验执行工具。

### 15.3 独立效度验证后

仅在相应外部验证获得支持时允许：

- DRRL 与指定复用范围内的独立第三方复用成功和可避免摩擦具有经验证的关系；
- ERL 在指定 Cluster、任务、应用范围和模型集合内，与未见案例的 zero-shot 表现
  和失效风险具有经验证的关系。

任何阶段均禁止：

- 将 DRRL 与 ERL 合成为总分；
- 将 ERL 解释为目标准确率上下界或成功保证；
- 将 DRRL 解释为工程域迁移能力；
- 将单个目标案例、模型或随机种子作为普遍效度证据；
- 将不可评、未知或冲突自动解释为最低等级；
- 将模型自报结论视为 Q3 证据。

## 16. 尚未冻结的内容

以下内容须在相应先导或开发阶段确定：

- 正式 `registry_lock` 中的家族与发布单元数量；
- 各 Cluster 的主效度任务和应用范围；
- ERL 可评单元数 (N_E) 及其审计、重复样本数；
- DRRL 独立效度研究的发布版本数和操作者数；
- ERL 开发与验证源数据集数；
- 各 Cluster 的正式目标案例数和案例内样本量；
- 冻结模型集合、训练预算和随机种子数；
- DRRL 摩擦切点和 ERL `V` 判据阈值；
- Cluster—任务主要性能终点、灾难性失败定义和主要风险终点；
- 正式功效分析、层级模型和多重性处理细节。

这些内容不得在观察独立验证结果后补定。每次实质性修订必须更新版本、形成变更
记录，并明确原验证材料是否仍保持独立。
