## 合并方法

1. 从 S2 的 JSONL 附录建立家族级骨架；不继承其总数断言。
2. 从 S1、S3、S4 提取候选名称，先做别名表，再与骨架合并。
3. 对同一采集来源的任务扩展、重新标注、对齐版和聚合版建立版本节点，不新增家族。
4. 对四源冲突的 DOI、许可、规模、模态和数据仓库，用数据 DOI、官方项目页、论文出版页或发布团队仓库核验。
5. 单独保留 `eligibility_status`、`scope_fit`、`public_asset_state` 和 `evidence_grade`，避免把“未核验”写成“不满足”。
6. 不计算 DRRL、ERL、模型性能或 zero-shot 结果。

## 状态迁移规则

### `provisional → include`

必须至少满足：

1. canonical title、发布团队和稳定主来源可唯一识别；
2. 场景、模态和任务符合冻结后的 A/B/C/D 边界；
3. 存在公开分发声明或可核验资产，哪怕访问需要注册/申请；
4. 版本归属清楚，不是未声明的镜像或同一数据的重新打包。

### `include → provisional/exclude`

出现以下任一情况就回退：

- 主来源无法取得任何数据或文件清单，且发布者未声明受控申请流程；
- 许可证、访问协议与“公开复用”定义相冲突；
- 数据模态或标签任务不符合 Cluster 定义；
- 发现只是模型仓库、数据聚合器、论文私有集或第三方商业重打包。
