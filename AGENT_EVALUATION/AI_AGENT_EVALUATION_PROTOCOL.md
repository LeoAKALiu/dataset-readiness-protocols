# DRRL/ERL 多 Agent 证据评价实验协议

## 0. 文档状态

- 状态：阶段 0 前候选协议。
- 日期：2026-08-19。
- 适用范围：城市更新/城市体检相关公开数据集的 DRRL 与 ERL 评价。
- 当前注册表：98 个 `include + provisional` 数据集家族；正式数量以未来
  `registry_lock` 为准。
- 本协议不继承旧 48 数据集清单、编号、评价结果或模型实验结果。

阶段 0 完成后必须建立不可变的协议锁定记录 `protocol_lock`。在该记录形成前，不得将
本文件表述为已预注册的正式实验版本。

## 1. 目标与非目标

### 1.1 目标

建立一套低人工干预、可核验、可中断恢复且可由后续模型面板复用的证据评价流程：

```text
预先固定数据集身份与任务范围
→ 检索 Agent 提出逐字段证据
→ 盲核验 Agent 独立抽取
→ 确定性比较器对齐字段
→ 必要时第三 Agent 复核
→ 确定性指标计算程序生成 Q3 指标
→ 确定性判定程序依据预先固定的 DRRL/ERL 协议生成结果
→ 输出等级、完备度、阻塞项和证据链
```

同时通过人工参考集、五模型审计和测试—重测审计，评价该流程的准确性、
覆盖率、一致性和失败模式。

### 1.2 非目标

- 不以本实验比较或排名通用模型能力；
- 不以模型多数表决确定事实或等级；
- 不把网络、限流或 OAuth 服务错误归因给数据集；
- 不用 Agent 估算本可由程序直接计算的指标；
- 不把 DRRL 与 ERL 合成为总分；
- 不使用目标工程案例结果反向修改 ERL 评价；
- 不预先承诺 Agent 方法一定构成论文创新点。

## 2. 构念、评价单元与层级

### 2.1 构念边界

- DRRL：第三方能否低障碍、可核验地复用指定发布版本。
- ERL：指定发布版本在预先界定的工程应用范围内所具有的前置工程域迁移潜力证据。

两者共享身份和原始来源，但独立裁决。DRRL 等级不能作为 ERL 准入等级；ERL
等级也不能改变 DRRL。

### 2.2 三层证据图

| 层级 | 稳定标识 | 主要证据 |
|---|---|---|
| 家族节点 | `family_key` | 身份、发布方、采集/派生谱系、版本关系 |
| 发布节点 | `release_key` | 许可、入口、文件、划分、标注版本、发布清单 |
| 任务节点 | `evaluation_unit_id` | Cluster、任务范围、语义、监督、有效样本和 ERL 指标 |

子节点引用父节点证据，不复制事实。父证据失效或版本改变时，所有受影响子节点
必须进入 `REVALIDATION_REQUIRED`，重新核验或重算。

### 2.3 正式评价单元

- DRRL：`family + explicit release + reuse scope + assessment time`。
- ERL：`family + explicit release + Cluster + application envelope`。

发布物、标签、划分、许可、支持任务、对齐方式或实际数据发生实质变化时拆分
发布单元；仅元数据排版、文件名或内容不变镜像不拆分。

复合数据集可以作为独立发布产品评级，但必须标记 `composite`、建立源依赖图，
并在 ERL 有效样本计算前执行跨成员去重。复合产品不作为独立采集家族增加总体
统计权重。

### 2.4 汇总权重

所有发布/任务单元均保留正式结果。总体比例、Cluster 比较、置信区间和 bootstrap
以家族为聚类单位，每个家族总权重相同。报告必须同时给出家族数和评价单元数。

## 3. 统一 Pi Agent 执行框架

### 3.1 公共框架

五个模型均通过同一预先固定版本的 Pi Agent 执行。正式协议锁定记录至少包括：

- Pi Agent 版本或 commit；
- provider adapter 版本；
- 工作区与扩展配置哈希；
- 公共工具注册表、权限和版本；
- 角色提示词、schema 和确定性判定程序的哈希；
- OAuth 路由、账户服务等级、模型别名和可获得的实际模型标识；
- 已暴露的模型参数及实际值。

OAuth 只负责认证和模型传输。凭据不得写入仓库。未暴露的温度、seed、隐藏系统
提示等记为 `PROVIDER_MANAGED`，不猜测默认值，也不作为模型纳入研究的必要条件。

### 3.2 公平条件

- 所有模型使用同版公共任务、Cluster 字典、角色适配器和输出 schema；
- 只允许为适配供应商调用语法而变化，不允许改变证据义务；
- 正式实验禁用不能向全部模型等价提供的供应商原生搜索/浏览工具；
- 所有外部访问通过 Pi 公共只读工具层和同一网络缓存；
- 不根据预期能力为某模型增加上下文、搜索预算或人工帮助。

论文只能声称“同一受控 Agent 执行框架”，不能声称供应商内部运行条件完全相同。
比较对象应写作：

```text
模型 × OAuth 路由 × provider adapter × 预先固定的 Pi Agent 框架
```

### 3.3 模型面板与槽位

当前候选面板包括 GPT-5.6 Sol、GLM-5.3、Kimi-K3、Grok-4.6 和
Gemini-3.7-Flash；精确路由以阶段 0 可观察信息为准。

`panel_manifest` 按规范化 `provider/model_id` 字典序映射到 P1–P5。不得按主观
能力安排关键槽位。升级、替换或面板变化必须创建新的 `panel_id` 和 `run_id`，
不得覆盖旧结果。

模型版本由研究者在快速实验窗口内人工关注；本协议不额外设置时间漂移分块或
模型指纹测试。仍须逐调用记录时间和可观察模型标识。确认版本变化时暂停并新建
`run_id`。

## 4. 角色与职责分离

### 4.1 检索 Agent

检索 Agent 按字段寻找最接近原始事实的来源，输出候选证据包。它不得：

- 决定 DRRL/ERL 等级；
- 以模型记忆替代来源；
- 把二手来源升级为事实；
- 自行执行未经允许的代码、注册、协议接受或付费操作；
- 查看其他 Agent 的检索路径、候选值或结论。

### 4.2 盲核验 Agent

核验 Agent 与检索 Agent 必须为不同槽位。核验时只接收：字段定义、数据发布单元
身份、来源 URL 和定位信息；在提交独立抽取前，不得看到检索者的候选值、摘录和
结论。

核验者若发现检索者遗漏的新证据，标记 `PROPOSED_BY_VERIFIER`。该证据须由原
检索者或第三 Agent 再确认后才可进入 `ACCEPTED`。

### 4.3 第三 Agent

字段标准化比较输出 `MATCH`、`MISMATCH` 或 `NOT_COMPARABLE`。发生实质冲突、
新增证据或来源权威性不明确时，由第三 Agent 复核。第三 Agent 可看到去除模型
身份后的两份证据包和冻结来源，不得以模型票数裁决。

第三复核仍无法解决时，输出 `UNRESOLVED_AFTER_REVIEW`；主评价流程不进行人工
内容裁决。

### 4.4 确定性程序

- DOI、URL、许可、日期、任务、模态、标签和数量单位由确定性标准化器处理；
- 近重复率、类别分布、有效样本量、配准误差和点密度等由 Cluster 指标计算程序生成；
- 程序记录代码版本、输入清单哈希、参数、随机种子和结果；
- Agent 可以核验程序输入和证据链，不得凭目测覆盖程序结果；
- 最终等级由确定性判定程序依据预先固定的协议生成。

## 5. 证据质量、权威性与持久化

### 5.1 质量层级

DRRL 与 ERL 统一采用 Q3–Q0：

| 级别 | 含义 |
|---|---|
| Q3 | 对实际数据、标签、元数据、采集记录或执行结果直接计算/复核 |
| Q2 | 对应版本的官方数据卡、许可、规范、论文、仓库或发布记录 |
| Q1 | 二手综述、非官方网页或不可复算声明，仅作线索 |
| Q0 | 无证据或冲突未解决 |

证据等级不是单一的全局来源排名。字段权威性按事实类型裁决：

- 许可/权利：当前正式许可文本或数据使用协议；
- 文件/标注：实际发布物、冻结清单和直接执行结果；
- 版本/发布身份：官方版本记录、归档和 DOI；
- 任务语义/采集协议：对应版本的官方数据卡、规范或原始论文；
- 论文身份：出版方和 DOI 注册记录。

同质量、同权威来源仍冲突时不得多数表决。

### 5.2 字段标准化

- DOI：小写，去除 URL 前缀；
- URL：规范化 scheme、host、默认端口、fragment 和可忽略追踪参数；
- 许可：SPDX 或冻结受控词表；
- 日期：ISO 8601；
- 任务、模态、标签：冻结受控词表；
- 数量：数值、单位和统计对象同时比较；
- 连续量：仅在计算字典预先声明的字段采用容差。

原始值与规范化值必须同时保留。

### 5.3 单字段证据包

每个字段至少保存：

- `protocol_lock_id`、`run_id`、`replicate_id`；
- 家族、发布和任务单元标识；
- 字段/判据 ID、角色和模型槽位；
- 原始值、规范化值、单位和适用性；
- URL、来源类型、访问时间、定位信息和必要短摘录；
- 页面/响应 SHA-256、HTTP 状态和缓存引用；
- Q0–Q3、字段权威范围和证据来源角色；
- 比较结果、核验结果、终态和父证据引用。

公开 schema 见 [`schemas/evidence-packet.schema.json`](schemas/evidence-packet.schema.json)。

### 5.4 公开与私有边界

公开：完整提示词、schema、非敏感配置、结构化输出、脱敏工具事件、URL、定位、
必要短摘录、内容哈希、指标代码、输入清单哈希和分析代码。

私有：OAuth 凭据、账户标识、隐藏推理、受版权限制的完整页面/数据副本、含敏感
信息的原始运行诊断记录。

合法缓存可私有保存；公开仓库只保存结构化证据、哈希和必要短摘录。不得要求
公开模型隐藏思维过程。

## 6. 证据状态与协议状态

### 6.1 Agent 证据终态

| 状态 | 含义 |
|---|---|
| `ACCEPTED` | 来源已由独立核验确认，可作为确定性判定程序的输入 |
| `REJECTED` | 候选证据不支持该字段或来源无效；不等于协议判据 FAIL |
| `NOT_EVIDENCED` | 完成规定检索后，来源本身未提供可核验证据 |
| `NOT_APPLICABLE` | 按冻结任务—模态规则不适用 |
| `ACCESS_BLOCKED` | 经归因核验确认的数据源访问障碍 |
| `UNRESOLVED_AFTER_REVIEW` | 第三复核后仍存在实质冲突 |

`RUN_INCOMPLETE`、`PENDING_RETRY` 和 `REVALIDATION_REQUIRED` 是运行状态，不是
证据终态，不能生成正式评级结果。

### 6.2 到 DRRL/ERL 判据的映射

- `ACCEPTED` 证据由确定性判定程序依其内容支持 PASS 或 FAIL；
- `REJECTED` 只淘汰候选证据，不直接形成判据 FAIL；
- `NOT_EVIDENCED` 映射为协议的 `UNKNOWN`；
- `NOT_APPLICABLE` 映射为 `N/A`/`NA`；
- `UNRESOLVED_AFTER_REVIEW` 映射为 `CONFLICT` 或未确认；
- `ACCESS_BLOCKED` 对 DRRL 访问/获取判据按直接执行规则裁决；对 ERL 表示资产
  不可评，不得映射为低 ERL；
- `RUN_INCOMPLETE` 不得进入确定性判定程序。

### 6.3 单元完成条件

一个评价单元只有在全部必填字段均进入合法终态，且不存在待重试、待核验或
`RUN_INCOMPLETE` 时才完成。`UNRESOLVED_AFTER_REVIEW` 是“流程完成但证据不确定”
的终态，可输出可验证等级下界与完备度。

## 7. 外部访问控制、检索终止与异常处理

### 7.1 同一运行内的响应固定

同一 `run_id` 内，标准化 URL 或检索请求首次成功返回后，冻结响应内容、时间和
哈希；后续 Agent 读取同一版本。新 `run_id` 重新获取，不自动沿用旧快照。

共享缓存不等于共享 Agent 工作记忆。不同 `replicate_id` 必须使用相互独立的新上下文，
且不得获取其他 Agent 的查询、来源选择、抽取值或结论。

### 7.2 检索停止

证据完成契约优先于资源预算。所有必填字段已有可核验证据，或连续两个规定检索
轮次没有新增必填证据时，触发内容停止。检索轮次的查询模板与来源覆盖要求须在
阶段 0 冻结。

预算仅用于资源调度和异常使用预警。达到统一的绝对安全上限时，任务只能暂停并记为
`RUN_INCOMPLETE`；恢复后从检查点继续，不得使用不完整证据进行评级。

### 7.3 异常分类与重试规则

- 超时、断开、429、5xx：遵循 `Retry-After` 或指数退避加抖动；
- 输出截断/schema 错误：先进行一次确定性格式校正；若仍失败，则在相互独立的
  新上下文中重新执行该角色；
- 证据缺失/语义冲突：不作为服务错误，进入补充检索或第三复核；
- 达到服务安全上限：暂停并记为 `RUN_INCOMPLETE`，待条件恢复后从已记录检查点继续执行。

传输或服务异常所引发的重试沿用原 `replicate_id`，不视为独立实验重复，也不计入
正式证据检索预算。重试次数和等待上限由阶段 0 预先固定。

### 7.4 运行诊断记录隔离

运行维护与诊断记录必须与评价结果的持久化文件使用不同目录、schema 和生命周期。评价结果文件
仅包含合法的结构化输出及必要的运行摘要，不得包含重试堆栈、临时提示、诊断对话或
校正过程。

## 8. 访问障碍归因与独立第三方条件

DRRL 首先在无 Cookie、无个人特权的全新会话中测试。若平台要求任何第三方都能
低门槛注册的普通账户，可使用标准实验账户并记录步骤。机构资格、人工审批、
邀请、付费或特殊地区条件属于真实访问障碍。

只有同时满足以下条件才可记 `ACCESS_BLOCKED`：

1. 网络与工具控制页面正常；
2. 完成冻结重试并尝试声明的其他官方入口；
3. 检索者和核验者独立复现，冲突时经第三 Agent 复核；
4. 保存状态码、时间、URL 和响应哈希。

否则保持 `RUN_INCOMPLETE`。为 ERL 评价而依法采购或获准取得的数据资产，不得用于反向
改变或提高 DRRL 中的第三方访问状态。

Agent 不创建账户、接受法律条款、提交审批、购买产品或发送外部消息。必要的
法律/账户动作由授权人员完成并作为干预记录。

## 9. ERL 资产资格与计算

ERL 不设最低 DRRL 门槛。数据资产进入 ERL 评价前，必须满足以下独立可评性条件：

- 发布版本身份唯一；
- 数据已合法取得或具有完整逻辑访问；
- 完整文件/分区/标注清单能够枚举；
- 任务所需数据和标签可读取；
- 输入哈希、规模和缺失情况可核验。

大型或在线托管数据集不强制完整本地下载，但必须完整逻辑访问。低成本指标尽量
全量计算；高成本指标只可使用 Cluster 字典预先冻结的确定性分层抽样，并报告
样本量、种子、覆盖层和不确定性。临时人工挑样无效。

未满足资产可评性条件时，记为 `NOT_EVALUATED`/`UNRATED`，不得赋予 ERL-0 或最低 ERL。

## 10. DRRL 与 ERL 盲化

两套评价流程共享预先固定的身份、版本、Cluster、应用范围和原始来源，但使用不同的证据
命名空间和提示词：

- DRRL Agent 看不到 ERL 指标、等级或数据测量结果；
- ERL Agent 看不到 DRRL 等级和复用障碍结论；
- 两套流程可并行执行，仅在各自结果固定后于分析阶段进行联结；
- 目标工程案例数据和表现对 ERL 评价完全屏蔽。

暂定联合分析底线：未评 ERL 记 `NOT_EVALUATED`，不插补为低等级，不生成联合
总分。具体 DRRL–ERL 联合分析待结果支持度明确后制定，并标为探索性。

## 11. 模型分配与运行规模

### 11.1 DRRL：98 家族主评价流程

P1–P5 形成 20 个检索者≠核验者的有向模型对。家族在 Cluster 内按冻结哈希排序，
尽量交错 `include/provisional`，使用确定性平衡轮换。模型的检索/核验次数和每个
有向对使用次数应尽量相等；分配表在运行前公开。

DRRL 主评价流程的角色执行次数为：

\[
98\times 2=196
\]

### 11.2 DRRL：32 家族五模型审计

每 Cluster 8 家族，目标为 4 `include` + 4 `provisional`；至少 8 个家族具有多版本、
派生或复合谱系。阶段 0 的 8 个家族排除在正式 32 家族审计集之外，
避免用于校正实验框架的案例同时成为方法审计样本。样本在正式评价前由公开
哈希算法完成。

每个审计家族由五个模型各担任一次检索者和一次核验者。核验偏移量
`d∈{1,2,3,4}` 在 32 家族中各分配 8 个，并在 Cluster 内平衡：

\[
P_i \rightarrow P_{1+((i-1+d)\bmod 5)},\quad i\in\{1,2,3,4,5\}
\]

从而覆盖全部 20 个有向模型对。

### 11.3 DRRL：16 家族重复审计

从 32 家族内再选每 Cluster 4 个，目标为 2 `include` + 2 `provisional`。五组完整的
双 Agent 证据评价流程使用相同模型配对、同一运行缓存、相互独立的新上下文和新
`replicate_id`，并独立重复一次。

DRRL 固定的角色执行次数为：

\[
98\times2 + 32\times8 + 16\times10 = 612
\]

不包括服务重试、阶段 0 和确定性指标计算程序。

### 11.4 ERL 附加运行数

DRRL 与 ERL 使用不同提示词、不同证据命名空间和独立角色执行，因此 612 不能
代表整项 DRRL+ERL 实验的总执行次数。ERL 资产可评性结果固定后定义：

- \(N_E\)：全部可评 ERL 发布—任务单元数；
- \(N_{EA}\)：32 个审计代表性单元中可评 ERL 单元数；
- \(N_{ER}\)：16 个重复代表性单元中可评 ERL 单元数。

ERL 附加的角色执行次数为：

\[
2N_E + 8N_{EA} + 10N_{ER}
\]

其中，`2N_E` 表示全部 ERL 单元的主双 Agent 证据评价流程；`8N_EA` 表示审计单元在
主评价流程之外新增的四组双 Agent 证据评价流程；`10N_ER` 表示五组流程的独立重复。
整项研究的角色执行次数为：

\[
612 + 2N_E + 8N_{EA} + 10N_{ER}
\]

ERL 不可评单元不产生 ERL Agent 角色执行。若 32/16 家族与 ERL 可评集的交集在
某 Cluster 过小，ERL Agent 审计只能报告实际覆盖，不得声称保持 8/4 家族平衡；
也不得依据 ERL 等级方向事后补样。

### 11.5 主分析结果与审计结果的隔离

每个家族预先指定一组 `primary_pipeline`。98 个家族的正式等级仅使用主评价流程证据。
审计家族额外四组评价流程和重复执行结果保存于独立命名空间，仅用于准确性、
可靠性和敏感性分析。五组评价流程的证据并集仅可作为探索性结果单独报告，不得替代
主分析结果。

## 12. 人工参考真值

人工参考仅覆盖 32 个审计家族的代表性评价单元（sentinel unit）：

- 每 Cluster 学生作为主核验者；
- 第二名学生轮换核验全部必要性判据、等级决定字段以及预先固定抽样中的描述性字段；
- 两人均在 Agent 输出和等级解盲前独立工作；
- 仅人工之间仍有分歧时由项目负责人裁决；
- 人工参考冻结后才与 Agent 结果比较；
- 人工参考不覆盖或改写主 Agent 原始输出。

所有影响等级的字段必须进入人工参考。纯描述性字段可以确定性分层抽样；抽样率
和字段清单在 `protocol_lock` 中冻结。

## 13. 统计原则

统计单位为数据集家族的代表性评价单元，不得将字段、模型执行或重复测量视为独立数据集。
32 家族分析按 Cluster 分层、以家族为单位 bootstrap。

分别报告：

1. 相对人工参考的准确性；
2. 五组评价流程之间的一致性；
3. 16 家族测试—重测稳定性；
4. 错误引用、遗漏、冲突、错误确定结论和运行不完整率。

分类状态报告精确一致率、Gwet's AC1/AC2 或 Krippendorff's alpha 及置信区间；
数值字段报告精确/容差一致率和误差分布。不把这些维度加权成 Agent 总分。

对人工可判定字段同时报告：

- 解析覆盖率；
- 已确定输出的条件准确率；
- 全部可判定字段的总体正确解析率。

`UNRESOLVED_AFTER_REVIEW` 降低覆盖率和总体正确解析率，但不作为虚假断言进入
条件准确率。错误的确定结论明确计错。

## 14. 安全与提示注入

网页、PDF、README、仓库文件和数据卡均为不可信证据，不能改变系统提示、协议、
权限或 schema。Agent 不执行来源中的命令、脚本、登录、下载或消息指令。数据
下载、解压、格式检测和指标计算由独立受限程序完成。

发现疑似提示注入时记录 `UNTRUSTED_INSTRUCTION_DETECTED` 及来源片段，但不把
安全事件当作数据集扣分项。

## 15. 阶段、冻结与变更

### 15.1 阶段 0

8 个家族试运行（每 Cluster 一个 `include`、一个 `provisional`）仅用于验证执行框架，
不设模型准确率阈值。输出不进入正式评价结果。

阶段 0 可校正协议歧义、schema 缺陷、工具适配问题和不可计算条目，所有变化均须进入
变更日志。

### 15.2 正式协议锁定记录

阶段 0 通过后，同时固定注册表、协议、四个 Cluster 字典、提示词、schema、确定性
判定程序、指标计算程序、模型面板、抽样清单、模型对分配、重试/停止规则和统计计划。

GitHub 以带日期 tag/release 公开 `protocol_lock`。正式运行后的实质缺陷必须暂停、
发布新的锁定记录，并统一重新执行或计算所有受影响单元；不允许仅对个别单元作定向修改。

## 16. 完成边界

整项实验采用以下组件完成判据：

- `DRRL_PRIMARY_COMPLETE`
- `ERL_ELIGIBILITY_COMPLETE`
- `ERL_PRIMARY_COMPLETE`
- `DRRL_AGENT_AUDIT_COMPLETE`
- `ERL_AGENT_AUDIT_COMPLETE`
- `DRRL_REPEAT_AUDIT_COMPLETE`
- `ERL_REPEAT_AUDIT_COMPLETE`
- `HUMAN_REFERENCE_COMPLETE`
- `ANALYSIS_COMPLETE`

每项完成判据记录预期数、完成数、合法终态数、未完成数及内容哈希。存在必需的
`RUN_INCOMPLETE` 时不能宣称整体实验完成。机器可读格式见
[`schemas/completion-manifest.schema.json`](schemas/completion-manifest.schema.json)。

## 17. 论文表述边界

Agent 方法贡献按结果分级：

- 准确性、覆盖率、跨模型一致性和重复性均较高，且各 Cluster 无系统性失效：
  可作为经经验验证的双 Agent 评价方法；
- 结果总体可用但存在局部不稳定：作为具有可行性证据的半自动框架；
- 结果不足：仅作为透明实验工具，论文创新由 DRRL/ERL 构念、协议和实证承担。

无论结果如何均报告置信区间、失败类型和适用边界，不以某模型显著优于另一模型
作为主要结论。
