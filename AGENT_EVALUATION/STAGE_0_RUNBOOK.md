# 阶段 0：Pi Agent 执行框架验收与试运行

## 1. 目的

阶段 0 只验证实验装置能否稳定、完整地执行候选协议。它不比较模型能力，不估计
正式 Agent 准确率，也不产生数据集正式 DRRL/ERL。

## 2. 输入锁

启动前保存候选输入清单：

- 当前家族注册表及 SHA-256；
- DRRL/ERL 核心协议和 A/B/C/D 字典 commit；
- 候选提示词、schema、规则引擎和指标程序 commit；
- Pi Agent、provider adapter、工具注册表和工作区配置；
- 五模型候选 `panel_manifest`；
- 阶段 0 样本选择脚本版本。

这些输入形成 `stage0_candidate_lock`，但不等同于正式 `protocol_lock`。

## 3. 试运行样本

使用 8 个家族：每个 Cluster 两个，分别为一个 `include` 和一个 `provisional`。
样本由 [`scripts/select_audit_families.py`](scripts/select_audit_families.py) 的
`stage0` 输出确定，不人工挑选。

阶段 0 可以使用每个家族的候选 sentinel 发布/任务单元。正式 sentinel 规则须在
阶段 0 后冻结：

1. 当前官方稳定发布优先；
2. 原生支持 Cluster 主任务的发布优先；
3. 信息仍相同则采用最新明确发布；
4. 再相同则以 `release_key` 哈希破同分。

不得使用 DRRL/ERL 预估等级选择 sentinel。

## 4. 技术验收项目

五个模型均须在统一 Pi Agent 中完成下列技术功能：

| 编号 | 验收项目 | 通过条件 |
|---|---|---|
| S0-1 | OAuth 调用 | 返回可记录的模型响应和可观察路由信息 |
| S0-2 | 公共工具 | 能使用同一检索、页面读取和证据记录工具 |
| S0-3 | 检索角色 | 能生成 schema 合法的候选证据包 |
| S0-4 | 盲核验角色 | 不读取候选值，能独立抽取并提交 |
| S0-5 | 第三复核 | 能处理冻结冲突包且不按模型身份投票 |
| S0-6 | schema 修复 | 确定性修复或干净上下文重跑后合法 |
| S0-7 | 断点续跑 | 人工注入可恢复服务错误后从检查点继续 |
| S0-8 | 缓存隔离 | 同 run 共享冻结响应，不共享 Agent 工作记忆 |
| S0-9 | 日志隔离 | 调试日志不进入评分持久化目录 |
| S0-10 | 规则引擎 | 只消费合法终态证据，不消费 `RUN_INCOMPLETE` |

不得设置证据准确率或最低等级作为阶段 0 准入门。失败首先修复公共适配层；若某
OAuth 路由仍不能运行，则记 `HARNESS_INCOMPATIBLE`，正式实验不得在声称五模型
面板的同时静默删去该模型。

## 5. 故障注入

至少在非正式样本上验证：

- 429/5xx/超时后遵循退避并沿用原 `replicate_id`；
- 响应截断或 JSON 格式错误先确定性修复，失败后干净重跑；
- 进程终止后能从最后一个原子检查点恢复；
- 服务错误重试不增加科学重复次数；
- 安全上限只暂停 `RUN_INCOMPLETE`，不生成等级；
- 页面内容改变时，同一 `run_id` 仍读取首次成功冻结版本；
- 新 `run_id` 不自动继承旧网页快照。

## 6. 检索轮次和软预算校准

阶段 0 记录每个模型/角色/Cluster 的：

- 标准化搜索请求数；
- 页面打开数；
- 工具调用数；
- 新增必填证据数；
- 墙钟时间和主动计算时间；
- 运输/服务重试；
- schema 修复与角色重跑。

据此冻结“一个检索轮次”的查询模板、来源覆盖和结束条件。内容停止仍为：必填
证据完成，或连续两轮无新增必填证据。

模型专属资源值仅形成软预警。统一绝对安全上限用于防止失控任务，触发后暂停并
允许恢复；不得据此以不完整证据评分。

## 7. 允许和禁止的修改

阶段 0 允许：

- 消除字段歧义；
- 修复 schema 和标准化器；
- 修复 Pi/provider adapter；
- 把不可计算的字典条目改写为可执行定义；
- 补全错误分类、重试和终态条件。

阶段 0 禁止：

- 根据试运行等级方向调整门槛；
- 为某模型定制更容易的证据义务；
- 将试运行结果并入正式统计；
- 使用目标工程案例表现修改 ERL；
- 删除困难家族以提高完成率。

所有修改写入 `stage0_change_log`，包括旧值、新值、原因、受影响文件和验证结果。

## 8. 退出条件

只有同时满足以下条件才能创建正式 `protocol_lock`：

1. 五个模型均完成全部技术验收，或研究者公开重定义模型面板；
2. 8 个家族的候选流程全部达到合法终态；
3. 故障注入和断点恢复通过；
4. schema、标准化比较器和规则引擎测试通过；
5. 调试/评分目录隔离通过；
6. 检索轮次、软预警和安全上限已冻结；
7. 阶段 0 变更日志完整；
8. 阶段 0 输出已标记 `EXCLUDED_FROM_FORMAL_ANALYSIS`；
9. 正式注册表、审计样本、模型对和统计计划可以生成。

退出后必须从干净上下文重新运行正式样本；不得把阶段 0 缓存、证据包或等级复制
到正式结果。
